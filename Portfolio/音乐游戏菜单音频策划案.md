# 音频策划案 —— 音乐游戏菜单系统的交互式音频设计

> 项目：《Cytus II》风格主菜单 Demo（Unity + Wwise 复刻）
> 类型：交互式音频 / 音乐游戏 UI 音频设计
> 定位：应聘音频策划作品集 —— 展示"从听感定位 → 系统设计 → 中间件实现 → 数据落地"的完整音频设计链路
> 版本：v1.0

---

## 0. 一句话概述

以"音乐随界面流动（Seamless Music Flow）"为核心体验，用 Wwise 的 **Music Switch Container + Music Playlist Container** 构建一条贯穿主菜单 / 选角 / 选曲 / 游戏四态的连续音乐流，配合一套统一的 UI 音效反馈与精确停播的歌曲预览系统，让界面操作像翻开一张专辑而不是切换页面。

---

## 1. 项目概述

### 1.1 背景与设计目标

音乐游戏的主菜单本身就是"听觉门面"。玩家在进入第一首曲子之前，先感受到的是菜单音乐的气质与界面反馈的手感。本项目复刻《Cytus II》主菜单到选曲的完整流程，音频侧要解决三件事：

1. **音乐不"断"**：界面切换时音乐保持连续、有节奏感地换段，而非生硬地停一首、起一首。
2. **角色有"声音人格"**：选角时每个角色绑定专属主题曲，切换角色即切换主题，强化角色个性。
3. **操作有"手感"**：悬停、点击、返回、确认有统一且克制的音效反馈，不喧宾夺主。

### 1.2 平台与技术基础

| 项目 | 内容 |
|---|---|
| 引擎 | Unity 2022.3 LTS（UGUI + TextMeshPro） |
| 音频中间件 | Audiokinetic Wwise 2025.1.9 |
| 目标平台 | Windows / Mac（Android 已生成 Bank，未做真机适配） |
| 集成方式 | Wwise Unity Integration（AkUnitySoundEngine，P/Invoke） |
| 采样率 / 码率 | 48 kHz，Vorbis 平均 64 kbps（音乐类） |

### 1.3 听觉定位与参考

- **整体基调**：电子 / 二次元电音（Eurobeat、Artcore、Hardcore 为主），中高速、强律动、合成器与女声为主。
- **统一调性基础**：主要角色主题曲与界面音乐统一在 **148 BPM**，为跨段转场提供可对齐的节拍网格（见 §4.3）。
- **参考对象**：《Cytus II》原版菜单、《Deemo》主菜单音乐流转逻辑。

## 2. 音频设计总纲

### 2.1 设计理念：分层与流动

```
┌─────────────────────────────────────────────────────┐
│  交互式音乐层 (Interactive Music)                     │
│   Menu_Music 单事件驱动 · 全程不断流 · 状态换段        │
├─────────────────────────────────────────────────────┤
│  角色主题层 (Character Theme)                         │
│   嵌套 Switch Container · 选角即换主题 · 无限循环       │
├─────────────────────────────────────────────────────┤
│  预览层 (Song Preview)                                │
│   独立事件 · PlayingID 精确停播 · 不干扰背景音乐        │
├─────────────────────────────────────────────────────┤
│  反馈层 (UI SFX)                                      │
│   Hover / Click / Back / Confirm · 走 SFX Bus         │
└─────────────────────────────────────────────────────┘
```

- **只切不重起**：菜单音乐 `Play_MenuMusic` 全程**只 Post 一次**，之后一律用 Switch 换段，从机制上杜绝"断流"和"两首叠加"。
- **音乐走路由 Wwise 负责**：转场淡入淡出、跳转位置全部交给中间件的 Music Transition 处理，游戏逻辑只负责"告诉 Wwise 现在在哪一层界面"。
- **音效与音乐分总线**：音乐走 `Music Bus`，音效走 `SFX Bus`，互不影响，便于独立做音量与后续混音。

### 2.2 听觉层级与音量关系

| 层级 | 内容 | 归属总线 | 相对响度定位 |
|---|---|---|---|
| 音乐 | 主菜单 / 角色主题 / 选曲 / 游戏 | Music Bus | 主体，-3 ~ -5 dB 素材预衰减 |
| 预览 | 歌曲试听片段 | Music Bus | 与背景音乐同级或略高 |
| 音效 | UI 四类反馈 | SFX Bus | 清晰但不刺耳，置于音乐之下 |

> 角色主题曲素材在 Wwise 内统一预置 **-3 dB**（neko 为 -5 dB，因其素材本身更"满"），使不同角色切换时主观响度均衡。

### 2.3 内容规模

| 类别 | 数量 | 说明 |
|---|---|---|
| 角色主题曲 | 8 首 | Cherry / ConneR / NaiLong / neko / paff / Robo_Head / sarflin / Xenon |
| 主菜单音乐 | 1 首 | MainMenu |
| 界面占位音乐 | 2 段 | SongSelect / InGame（暂为空 Segment，预留接口） |
| 歌曲预览 | 24 段 | 8 角色 × 约 3 首 |
| UI 音效 | 5 个 | UI_Hover / UI_Click / UI_Back / Character_Confirm / Song_Select |

## 3. 音频系统架构（Wwise 侧）

### 3.1 总线结构

```
Main Audio Bus（Master，输出设备：System）
├── Music Bus      ← RTPC: Music_Volume  → Bus Volume
│     └── MenuMusic / SongPreviews
└── SFX Bus        ← RTPC: SFX_Volume    → Bus Volume
      └── UI 音效
```

**设计要点**：`Music Bus` / `SFX Bus` 必须是 `Main Audio Bus` 的**子总线**，才能继承 System 输出设备。若建为平级 Master Bus 会被挂到 `No_Output`，导致全局静音（本项目实际踩过此坑，见开发记录）。

### 3.2 音乐容器层级

```
MenuMusic = Music Switch Container（Switch Group: Menu_Music, Tempo = 148）
├── MainMenu         Music Playlist Container（Loop = Infinite）
├── CharacterSelect  Music Switch Container（Switch Group: Character_Theme）
│     ├── Cherry     Music Playlist Container（Loop = Infinite）→ Segment: Cherry.wav
│     ├── ConneR     Music Playlist Container（Loop = Infinite）
│     ├── NaiLong    ...
│     ├── neko       ...（素材预置 -5 dB）
│     ├── paff       ...
│     ├── Robo_Head  ...
│     ├── sarflin    ...
│     ├── Xenon      ...
│     └── Non        （"未选角色"占位段，1 s 静默，-3 dB）
├── SongSelect       Music Segment（占位）
└── InGame           Music Segment（占位）
```

**为什么角色主题要包一层 Music Playlist Container**：Wwise 的 Music Segment 本身没有循环开关，裸 Segment 播完一次即停。无限循环必须由外层 Music Playlist Container 的 `Loop Count = Infinite` 提供。（这是本项目第一个被定位的音乐类问题。）

### 3.3 SoundBank 划分

| Bank | 内容 | Windows 体积 | 加载时机 |
|---|---|---|---|
| Init.bnk | 工程初始化、总线/设备信息 | ~0 | 引擎自动 |
| UI.bnk | 5 个 UI 音效 | 1.08 MB | 启动 |
| Music.bnk | 主菜单 + 8 角色主题 + 占位段 | 40.83 MB | 启动 |
| SongPreviews.bnk | 24 段歌曲预览 | 103.27 MB | 启动（待优化，见 §10） |

**划分原则**：按"使用频率 + 体积"分层。UI 与 Init 小且常驻；音乐与预览体积大，是后续做流式 / 按需加载的重点对象。

## 4. 交互式音乐设计（核心）

### 4.1 状态机：Menu_Music

| Switch State | 进入时机 | 音乐行为 |
|---|---|---|
| `MainMenu` | 启动 / 从子界面返回主菜单 | 播放主菜单曲（循环） |
| `CharacterSelect` | 玩家**明确选中**角色后 | 切到该角色主题曲（循环） |
| `SongSelect` | 确认角色进入选曲 | 停角色主题，切选曲段 |
| `InGame` | 开始游戏 | 切游戏段（占位） |

**关键体验决策**：进入选角界面时**不切音乐**，主菜单曲继续播放；只有玩家真正点选角色才切主题（方案 B）。这样避免"一进界面就听到默认角色曲"的突兀感，也让"选中"这个动作有明确的听觉回报。

### 4.2 角色主题：Character_Theme

- 选角界面滑动 / 点击角色 → 发送 `SetSwitch("Character_Theme", <角色名>)` → 嵌套 Switch Container 无缝切到对应角色 Playlist。
- 离开选角 / 返回主菜单 → 切到 `Non`（未选角色占位），避免主题曲残留。
- 返回选曲 → 选角时，恢复上一次选中角色的主题与高亮。

> 命名坑：Wwise 中"未选角色"状态因 `None` 是保留字而命名为 **`Non`**，必须与代码字符串完全一致，否则 `SetSwitch` 静默失败。

### 4.3 转场设计

转场由 Wwise 的 Music Transition 处理，统一规则：

- **源淡出**：`FadeTime = 0.2 s`，`FadeOffset = 0.2 s`（淡出与淡入略带重叠，避免"空格"）。
- **目标进入**：`Destination Jump Position Preset = 1`（从目标段的 Entry Cue 进入），`Enable Destination Fade-in = True`。
- **退出点**：`Exit Source At = 0`（立即退出源，由淡出曲线兜底）。
- **节奏对齐**：所有主题与界面音乐统一 **148 BPM**，各 Segment 设有 Entry Cue / Exit Cue，保证换段"踩在拍上"而非随机切断。
- **角色主题之间**：`CharacterSelect` 内层过渡显式启用源淡出 + 目标淡入，滑动切角色时做到"叠化"而非硬切。

### 4.4 音乐素材处理规范

- 歌曲前奏裁切：每个主题保留约 25.9 s 的可循环主体（`EndTrimOffset` 精确到毫秒），Entry Cue 标记循环起点。
- ConneR / NaiLong / neko 的剪辑曲线中额外挂了 Highpass / Lowpass / Volume 包络，用于段首的进出听感打磨。
- 音量统一在 Segment 属性上预置（-3 / -5 dB），而非事后靠调音台补偿。

## 5. UI 音效设计

统一走 `SFX Bus`，遵循"短、轻、齐"三原则：

| 事件 | 触发 | 设计意图 |
|---|---|---|
| `UI_Hover` | 鼠标悬停按钮 | 极轻的提示音，营造"可交互"的触感 |
| `UI_Click` | 点击任何按钮 | 明确的操作确认，短促 |
| `UI_Back` | 返回上级界面 | 音高/音色与 Click 形成方向感差异 |
| `Character_Confirm` | 选角界面二次点击确认 | 更"重"的确认音，标记重要节点 |
| `Song_Select` | 选曲界面选中歌曲 | 与预览切换同步的反馈 |

**设计考量**：悬停音控制在极短时长且低音量，防止快速滑动按钮时的"机关枪效应"；返回音与点击音在音色上做区分，让玩家闭眼也能判断操作结果。

## 6. 歌曲预览系统

### 6.1 行为契约

- 进入选曲界面即自动播放当前选中歌曲的预览。
- 点击 / 切换歌曲时**精确切换**：先 `StopPlayingID` 停掉上一首，再播放当前首，杜绝叠加与残留。
- 离开选曲界面立即停止，不残留。

### 6.2 实现要点

```
PlaySongPreview(song):
    StopSongPreview()                       // 先停旧
    playingId = PostEvent(song.previewEvent) // 记录 PlayingID
    if 失败 → 回退 AudioSource 播放 previewClip
```

- 每个预览是一个独立事件 `Play_Preview_<角色>_<歌曲>`，与背景音乐互不干扰。
- 用 **PlayingID 精确停播**而不是 `StopAll`，避免误伤正在循环的菜单音乐。
- **降级路径**：若 Wwise 事件缺失，自动回退到 Unity `AudioSource` 播放预览片段，保证 Demo 在无 Wwise 环境下逻辑仍可运行。

## 7. 音量与设置系统

### 7.1 RTPC 设计

| Game Parameter | 作用对象 | 曲线 | 初始值 |
|---|---|---|---|
| `Music_Volume` | Music Bus → Bus Volume | 0 → -200 dB，100 → 0 dB | 100 |
| `SFX_Volume` | SFX Bus → Bus Volume | 0 → -200 dB，100 → 0 dB | 100 |

- 滑块 0–100 整数，映射到 Bus Volume，0 即完全静音（-200 dB）。
- RTPC 采用 **Global 作用域**，用全局重载 `SetRTPCValue(name, value)` 设置（带 gameObject 的重载对 Global 参数不生效）。
- 用 `PlayerPrefs` 持久化两个值，重启后恢复。
- **启动即应用一次音量**，不依赖滑块 `onValueChanged`——因为值未变化时 Unity Slider 不触发回调，会导致 RTPC 从未被设置。

## 8. 命名规范与数据驱动

### 8.1 命名规范

| 类型 | 规范 | 示例 |
|---|---|---|
| 音乐事件 | `Play_<用途>` | `Play_MenuMusic` |
| 预览事件 | `Play_Preview_<角色>_<歌曲>` | `Play_Preview_Paff_Incyde` |
| UI 音效事件 | `UI_<动作>` / `<对象>_<动作>` | `UI_Click` / `Character_Confirm` |
| Switch Group | 语义化名词 | `Menu_Music` / `Character_Theme` |
| Switch State | 与界面 / 角色一致 | `MainMenu` / `paff` / `Non` |
| RTPC | `<用途>_Volume` | `Music_Volume` / `SFX_Volume` |

> **铁律**：Game Sync（Event / Switch / State / RTPC）命名大小写敏感，必须与 Wwise 完全一致。不一致不会报错，只会静默失效——这是音频集成最高发的隐性缺陷来源。

### 8.2 数据驱动

角色与歌曲信息用 `ScriptableObject` 承载，音频事件名 / Switch 名作为字段挂在数据资产上，与 Wwise 工程解耦：

- `CharacterData`：`characterName` / `wwiseSwitchName` / `wwiseEventConfirm` / `themeColor`
- `SongData`：`wwiseEventPreview` / `wwiseEventPlay` / `previewClip`（回退）/ `bpm` / 难度

新增角色或歌曲 = 新增一个数据资产 + 在 Wwise 侧加对应事件/ Switch 状态，**无需改代码**。

## 9. 引擎对接与实现

### 9.1 分层调用链

```
[UI 事件] MainMenuUI / CharacterSelectUI / SongSelectUI / SettingsUI
      ↓
[状态机] MenuManager（界面流转 + 转场时机 + 音频出入口）
      ↓
[音频管理] AudioSystemManager（Bank 加载 / 音乐状态 / 角色主题 / 预览 / UI SFX）
      ↓
[封装层] WwiseIntegration（PostEvent / SetSwitch / SetRTPC / LoadBank / 回退 AudioSource）
      ↓
[Wwise] AkUnitySoundEngine → Event → Music/Actor-Mixer → Bus → 系统输出
```

- 所有事件名、Switch 名在 Inspector 可配置，避免硬编码。
- 转场时在**两个时点**触发音频：`onExit`（离开界面）与 `onArrival`（到达界面），使音频与读条动画对齐。

### 9.2 音频出入口时机表

| 导航 | 退出时（onExit） | 到达时（onArrival） |
|---|---|---|
| 主菜单 → 选角 | 无（音乐不中断） | 初始化选角，不播角色主题 |
| 选角 → 选曲 | 停角色主题 | 切 SongSelect 态 + 初始化并播预览 |
| 选曲 → 选角 | 停预览 | 恢复上次角色主题 / 高亮 |
| 任意 → 主菜单 | 停预览 + 停角色主题 | 切 MainMenu 态 |

## 10. 性能预算与优化

| 指标 | 现状 | 目标 / 优化方向 |
|---|---|---|
| 启动 Bank 加载 | `Music.bnk` 40.8 MB + `SongPreviews.bnk` 103.3 MB 同步加载，有卡顿 | 音乐流式加载；预览按角色按需 / 异步 `LoadBankAsync` |
| 音频内存 | 预览 Bank 占比过高 | 24 段预览改为流式，或预览片段裁短 |
| 音乐切换 | 依赖 Wwise Music Transition，开销低 | 保持，无需游戏侧干预 |
| 实例数 | 菜单态最多 1 音乐 + 1 预览 + UI 音效 | 全局上限 256，无压力 |

**核心结论**：本 Demo 的音频性能瓶颈在**启动期大 Bank 同步加载**，而非运行时 DSP。后续版本优先做 Bank 拆分与流式化。

## 11. 风险与迭代规划

| 风险 | 表现 | 应对 |
|---|---|---|
| Bus 层级错误 | 全静音 | 构建后冒烟听声 + 核对 Init.json 总线路径 |
| Game Sync 命名不一致 | 静默失效 | 命名核验工具（比对 SoundbanksInfo.json） |
| 转场时序竞态 | 预览被误停 / 主题不恢复 | 明确音频出入口时机表，回归时序用例 |
| 大 Bank 同步加载 | 启动卡顿 | 流式化 + 异步加载 |
| RTPC 作用域不匹配 | 音量不可控 | 统一 Global + 启动强制应用 |

**迭代路线**：

1. **v1.1**：补齐 `SongSelect` / `InGame` 正式音乐段，接入游戏内音乐。
2. **v1.2**：预览 Bank 流式化与按角色按需加载，建立启动耗时基线。
3. **v1.3**：增加 Stinger（过场短动机）与转场音，丰富界面切换的听觉层次。
4. **v1.4**：落地命名核验 & 一键同步工具，把人工易错点转为自动化门禁。
